# Primnox Skill SDK Documentation

Welcome to the Primnox Skill SDK! The Skill SDK allows developers to extend the capabilities of Primnox by writing custom, modular "skills". Skills act as self-contained plugins that can be triggered by specific keywords, handle specific file extensions, and execute specialized tasks.

---

## 1. Core Concepts

At the heart of the Skill SDK are three primary classes located in `backend/skills/base_skill.py`:

1. **`SkillContext`**: The input context passed into every skill when it runs.
2. **`SkillResult`**: The typed object returned by a skill after execution.
3. **`BaseSkill`**: The abstract base class that all custom skills must inherit from.

### 1.1 `SkillContext`

When your skill is triggered, it receives a `SkillContext` dataclass containing the current context of the user interaction.

```python
@dataclass
class SkillContext:
    file_path: Optional[str] = None     # Path to an attached file, if any
    user_message: Optional[str] = None  # The user's original chat message
    session_id: Optional[str] = None    # The ID of the active chat session
    chat_history: list = field(...)     # List of past messages in the conversation
    metadata: dict = field(...)         # Extra metadata passed to the skill
```

### 1.2 `SkillResult`

After execution, your skill must return a `SkillResult` dataclass to tell the Primnox core what happened and what to output.

```python
@dataclass
class SkillResult:
    success: bool = True                # Did the skill execute successfully?
    output_text: str = ""               # Text to display to the user / return to the LLM
    output_path: Optional[str] = None   # Path to a file generated by the skill (optional)
    confidence: float = 1.0             # Confidence score (0.0 to 1.0)
    elapsed_ms: float = 0.0             # Auto-calculated execution time
    extras: dict = field(...)           # Any extra JSON/data to return
    error: Optional[str] = None         # Error message if success is False
```

### 1.3 `BaseSkill`

The `BaseSkill` class defines the interface for all skills. It manages the execution lifecycle (`before_execute`, `execute`, `after_execute`) and provides a standard schema.

**Class Properties you must/can define:**
- `name` (str): The readable name of your skill.
- `description` (str): A description of what the skill does (used by the LLM).
- `supported_extensions` (tuple): File extensions this skill handles (e.g., `(".pdf", ".txt")`).
- `trigger_words` (tuple): Keywords that immediately trigger this skill (e.g., `("schedule", "calendar")`).
- `REQUIRES_SYSTEM` (tuple): System-level dependencies required.
- `REQUIRES_PIP` (tuple): Python package dependencies required.

## 2. How to Build a New Skill

Follow these steps to create a new skill in Primnox:

### Step 1: Create a Python file
Create a new file in the `backend/skills/` directory ending in `_skill.py`. For example, `weather_skill.py`. The `skill_router` automatically discovers files matching the `*_skill.py` glob.

### Step 2: Inherit from `BaseSkill`
Import `BaseSkill`, `SkillContext`, and `SkillResult` from `base_skill`. Create a class that inherits from `BaseSkill`.

### Step 3: Define Metadata
Set the `name`, `description`, `trigger_words`, and `supported_extensions`.

### Step 4: Implement `execute()`
Override the `execute` method to contain your logic. It takes a `SkillContext` and must return a `SkillResult`.

## 3. Example Implementation: Weather Skill

Here is a complete example of a simple skill that triggers when a user asks about the weather.

```python
# backend/skills/weather_skill.py
import requests
from .base_skill import BaseSkill, SkillContext, SkillResult

class WeatherSkill(BaseSkill):
    name = "Weather Fetcher"
    description = "Fetches the current weather for a given city."
    
    # The skill will intercept messages containing these words
    trigger_words = ("weather", "temperature", "forecast")
    
    # We don't process specific file types for this skill
    supported_extensions = ()

    def execute(self, ctx: SkillContext) -> SkillResult:
        message = ctx.user_message.lower() if ctx.user_message else ""
        
        # Simple extraction logic (in a real skill, you might use regex or an LLM)
        city = "New York"
        if "in " in message:
            city = message.split("in ")[-1].strip()

        try:
            # Example API call (assuming a hypothetical wttr.in endpoint)
            resp = requests.get(f"https://wttr.in/{city}?format=3")
            if resp.status_code == 200:
                weather_data = resp.text.strip()
                return SkillResult(
                    success=True,
                    output_text=f"Here is the weather for {city}:\n{weather_data}"
                )
            else:
                return SkillResult(success=False, error="Failed to fetch weather.")
        except Exception as e:
            return SkillResult(success=False, error=str(e))
```

## 4. Execution Lifecycle

When a skill is triggered (either by a keyword or file extension), the `run(ctx)` method is invoked. This method manages the lifecycle:

1. **`before_execute(ctx)`**: (Optional) Override this to validate inputs or set up state before execution.
2. **`execute(ctx)`**: (Required) The core logic of your skill.
3. **`after_execute(ctx, result)`**: (Optional) Override this to clean up resources, format output, or log metrics.

All exceptions within these methods are caught safely, returning a `SkillResult` with `success=False` and the error attached to the `error` field, ensuring that a failing skill never crashes the Primnox backend.
